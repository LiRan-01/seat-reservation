# 功能与并发测试记录

> 撰写：佟思澄（测试与质量）
> 对应报告：第 6 章系统测试

## 一、测试怎么跑

两个脚本都在 `scripts/` 下，依赖已启动的全栈环境（`docker compose up -d --build`）：

```bash
bash scripts/acceptance-test.sh   # 功能验收，输出 PASS/FAIL
bash scripts/perf-test.sh         # 并发与性能，输出分位值与超卖数
```

2026-11-25 在 GitHub Actions（2 核 7 GB）上执行了完整一轮，原始输出随仓库提交在 `docs/实测结果/`，报告表 18、19、20 的数字都来自这一次执行。

## 二、结果摘要

- 功能验收：13 个场景全部 PASS，包括预约冲突拦截、签到码重放拦截、窗口外签到拒绝、暂离与返回、跨天预约、强制释放、超时释放与候补通知；
- 抢座：200 次请求落在 40 个座位上，成功 40、冲突 160、超卖 0；
- 座位图：150 次请求、30 并发，P50 204 ms、P95 310 ms（超 200 ms 目标）；
- 签到：40 并发，P50 29 ms、P95 49 ms；
- 定时任务：500 条过期预约一批处理完，耗时 883 ms。

## 三、测出来的两个真问题

1. **唯一键冲突返回 500**：并发抢座时，绕过 `countOverlap` 校验的请求会撞到数据库唯一键，最初直接抛 500。已加异常映射，统一返回 409 + `TIME_CONFLICT`，压测后 200 次请求里 160 次都是干净的冲突响应，没有服务异常；
2. **第二自习室座位缺失**：`init.sql` 生成座位用了会话变量写法，实际只插进去 20 个座位（21–31 号全部 `SEAT_NOT_FOUND`）。改成显式主键分配后，A 区 1–20、B 区 21–40 共 40 个座位正常。

这两条都不是"测试通过就算完"的问题，前者影响接口语义，后者影响演示数据完整性，所以都记进了缺陷记录。

## 四、没测到的部分

- 服务器时间漂移（ET-03）只做了逻辑校验，没有真去改容器时间；
- 任务执行延迟（ET-06）用人为阻塞验证的是顺延逻辑，没做长时间稳定性观察；
- 前端只做了手工点击验证，没有自动化 UI 测试。

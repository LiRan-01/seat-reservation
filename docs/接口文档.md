# 接口文档（智慧自习室座位预约与占座检测系统）

接口统一以 `/api` 为前缀，请求与响应均为 JSON。响应体固定为三段：

```json
{ "code": "OK", "message": "success", "data": {} }
```

`code` 为 `OK` 表示成功，其余为业务错误码（如 `TIME_CONFLICT`、`OUT_OF_WINDOW`、`CREDIT_LOW`）；HTTP 状态码只表达传输层语义，业务冲突统一返回 409。演示版不校验角色，`权限` 一列说明接口的用途归属。

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/rooms` | 查询全部自习室 | 学生 |
| GET | `/api/rooms/{roomId}/seats?start=&end=` | 按时段查询座位图与占用状态，不传时间默认当前到两小时后 | 学生 |
| POST | `/api/reservations` | 创建预约，返回预约单与签到码 | 学生 |
| GET | `/api/reservations?userId=` | 按学号查询本人预约 | 学生 |
| GET | `/api/reservations/{id}` | 查询预约详情 | 学生 |
| POST | `/api/reservations/{id}/away?minutes=` | 申请暂离，登记暂离截止时间 | 学生 |
| POST | `/api/reservations/{id}/back` | 返回座位，恢复使用状态 | 学生 |
| POST | `/api/reservations/{id}/cancel?userId=` | 取消未签到预约，释放座位 | 学生 |
| POST | `/api/reservations/{id}/finish` | 正常结束使用，置 RELEASED 并释放座位 | 学生 |
| POST | `/api/reservations/{id}/release?reason=` | 强制释放并记录处置原因 | 管理员 |
| POST | `/api/checkin` | 扫码签到，入参只有 token 与 deviceId | 学生 |
| POST | `/api/waitlist` | 候补登记 | 学生 |
| GET | `/api/notifications?userId=` | 按学号查询本人站内通知 | 学生 |
| GET | `/api/stats/occupancy?date=` | 按自然日查询上座率 | 管理员 |

## 关键约定

1. 签到接口不接受座位号，座位与预约信息全部从令牌解析，避免替他人签到。
2. 同一签到令牌不可重复使用（Redis `setIfAbsent` 校验一次性随机数），重复提交返回 `REPLAY`。
3. 预约冲突由数据库唯一索引 `uk_seat_start` 与服务层行锁共同保证，冲突返回 409 `TIME_CONFLICT`。
4. 签到窗口、爽约时限、信用门槛等参数在 `application.yml` 的 `app` 前缀下配置，调整规则不必改代码。
